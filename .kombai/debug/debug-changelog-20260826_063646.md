## Changes Made

### 1. Added a safe API base URL fallback
- **Files:** `frontend/src/services/api.js`, `frontend/src/services/auth.js`
- **Change:** Use `VITE_API_URL` when defined, otherwise fall back to `http://127.0.0.1:8000`; trim trailing slashes.
- **Why:** The missing environment variable produced requests to `http://localhost:5173/undefined/...`, causing Vite to return `index.html` and the app to fail while parsing HTML as JSON.
- **Revert:** Restore `const API_URL = import.meta.env.VITE_API_URL;` in both files.

### 2. Documented the frontend environment variable
- **File:** `frontend/.env.example`
- **Change:** Added `VITE_API_URL=http://127.0.0.1:8000`.
- **Why:** Provides the expected local API configuration for future frontend setup.
- **Revert:** Delete `frontend/.env.example`.

### 3. Added local backend environment configuration
- **Files:** `.env`, `.env.example`
- **Change:** Added local MySQL and JWT variables using development-only values; preserved the existing OpenAI variable in `.env`.
- **Why:** The backend had no database credentials, so `/events` could not connect even after the API URL was fixed.
- **Revert:** Remove the added MySQL/JWT entries from `.env` and `.env.example`.

### 4. Added a resilient events error state
- **Files:** `frontend/src/services/api.js`, `frontend/src/pages/Events.jsx`
- **Change:** Convert network failures to a clear Vietnamese message, preserve the original error as `cause`, and render an accessible error panel with a retry button.
- **Why:** A stopped backend should not leave the page looking blank or expose the browser's generic `Failed to fetch` message.
- **Revert:** Restore the original `getEvents` implementation and the original single-paragraph error branch in `Events.jsx`.

### 5. Added a Docker-independent local database path
- **Files:** `backend/app/database.py`, `backend/app/main.py`, `.env`, `.env.example`, `.gitignore`
- **Change:** Support an explicit SQLite `DATABASE_URL`, create ORM tables during FastAPI startup, make `/health/db` work with SQLite, and ignore the generated local database file.
- **Why:** Docker Desktop could not start because virtualization support was unavailable; local development needed a working database without masking the production MySQL option.
- **Revert:** Restore the MySQL-only database configuration and remove the SQLite startup/health handling and `*.db` ignore rule.

### 6. Added idempotent demo data for every domain table
- **Files:** `backend/seed_demo_data.py`, `database/init.sql`
- **Change:** Added reusable SQLite seed logic and matching MySQL `INSERT IGNORE` statements for users, speakers, events, sessions, registrations, feedback, FAQs, and notifications; kept the seed completion output ASCII-safe for Windows terminals.
- **Why:** The original SQL file contained only table definitions, so `/events` correctly returned an empty list even after the schema was created.
- **Revert:** Delete `backend/seed_demo_data.py` and remove the demo `INSERT` section appended after the schema in `database/init.sql`.

### 7. Added the missing admin entry route
- **File:** `frontend/src/App.jsx`
- **Change:** Added `/admin` redirecting to the protected `/dashboard` route.
- **Why:** Visiting `/admin` previously matched no route and rendered a blank page; the redirect now preserves the authentication guard and reaches the populated admin dashboard.
- **Revert:** Remove the `/admin` `<Route>` block.

### 8. Added GitHub onboarding files
- **Files:** `README.md`, `backend/requirements.txt`, `backend/seed_demo_data.py`
- **Change:** Documented local setup and deployment expectations, pinned backend dependencies, and made the seed script create the schema before inserting demo data.
- **Why:** A fresh clone needs an installable backend and a reproducible setup path without relying on the existing local virtual environment or database file.
- **Revert:** Delete `README.md` and `backend/requirements.txt`, and restore the seed script imports/startup behavior.

### 9. Added AI attendance-rate analysis
- **Files:** `backend/app/statistics_service.py`, `backend/app/schemas.py`, `backend/app/ai_service.py`, `backend/app/routers/ai.py`, `backend/app/routers/events.py`, `frontend/src/services/api.js`, `frontend/src/pages/AIAssistant.jsx`, `frontend/src/index.css`, `frontend/src/App.css`
- **Change:** Added a shared exact attendance aggregation helper, protected AI analysis endpoint, mock/OpenAI commentary service, authenticated frontend API client, and responsive result UI with loading/error/recommendation states.
- **Why:** The attendance percentage must be calculated from database records by the backend; AI is limited to human-readable commentary and recommendations.
- **Revert:** Remove the new statistics helper, schema/service/route/API/UI additions, and restore the original event statistics aggregation.

### 10. Fixed mobile admin layout overflow
- **File:** `frontend/src/App.css`
- **Change:** Stack the sidebar and main content below 700px, allow navigation items to wrap, reduce mobile content padding, and wrap the AI summary header.
- **Why:** The fixed 200px sidebar left too little width for the AI analysis cards on phones and caused horizontal scrolling.
- **Revert:** Restore the original mobile sidebar/main width rules and remove the mobile AI header wrapping properties.
